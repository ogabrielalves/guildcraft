Пиксельная мастерская гильдии, где каждый авантюрист это настоящий агент Claude Code. 🏰

Вы нанимаете по одному авантюристу на каждую папку проекта, и каждый из них это реальный процесс `claude`, запущенный в этой папке. Они сидят у своих станций, ходят по мастерской и меняют позу в зависимости от того, что агент делает на самом деле. Кликните по любому, и откроется его консоль. Попросите одного написать другому, и вы увидите, как сообщение идёт через всю комнату.

> Проект в разработке. Пока не опубликован.

## Что он делает

Когда запущено несколько сессий Claude Code в разных терминалах, быстро начинается путаница. Непонятно, кто сейчас думает, кто завис в ожидании разрешения, а кто закончил десять минут назад. Guildcraft собирает всех в одном месте и превращает состояние каждого агента во что-то, что видно с первого взгляда.

- **Один житель на проект.** Выберите папку, задайте имя и внешний вид, и там запустится агент Claude Code.
- **Статус, который видно.** Работает, простаивает, ждёт разрешения: об этом говорят поза и положение жителя, ничего открывать не нужно.
- **Настоящая консоль.** Кликните по жителю, и откроется его терминал. Это реальный TUI Claude Code, а не просмотрщик логов, и после перезагрузки страницы экран восстанавливается.
- **Разрешения прямо в интерфейсе игры.** Когда агент просит что-то выполнить, появляется карточка, и вы отвечаете на неё там же.
- **Агенты общаются друг с другом.** У каждого агента есть небольшой MCP-сервер с инструментами `list_villagers` и `send_message`. Когда один отправляет сообщение, его житель идёт к получателю, а само сообщение доставляется, как только получатель освободится.
- **История активности.** Модель, уровень усилий и список последних действий каждого агента, прочитанные из файлов сессий самого Claude Code.

Всё работает на вашем компьютере. Наружу не уходит ничего, кроме того, что Claude Code и так отправляет сам.

## Как это работает

```
 браузер (canvas + xterm)
        |  WebSocket
        v
 сервер guildcraft (Node) --- запускает ---> claude (в PTY, по одному на агента)
        ^                                        |
        | HTTP POST                              | hooks + MCP
        +------------ bin/hook.js, bin/mcp.js <--+
```

1. Вы создаёте агента в интерфейсе. Сервер записывает для него отдельные `settings.json` и `mcp.json`, которые направляют хуки и MCP Claude Code на вспомогательные скрипты guildcraft.
2. Сервер запускает `claude` внутри PTY (node-pty) и зеркалирует экран через headless-xterm, поэтому консоль можно восстановить позже.
3. Claude Code вызывает хуки (использование инструмента, остановка, уведомление и так далее). Скрипт хука отправляет их POST-запросом на сервер, тот превращает их в статус и рассылает по WebSocket.
4. Браузер получает статус, и житель меняет позу. Чтение транскрипта добавляет то, что хуки дать не могут: модель, уровень усилий и историю действий.
5. Для сообщений между агентами вызов MCP `send_message` попадает на сервер. Он рассылает событие визита (житель идёт к получателю) и держит текст в очереди, пока получатель не освободится, после чего вставляет его в его PTY.

Фронтенд это обычный движок на Canvas 2D без фреймворков. Персонажи, станции и карта описаны данными в `assets/`, так что смена графики или планировки не требует правок кода. Подробности в [docs/ASSETS.md](docs/ASSETS.md).

### Как агенты находят друг друга

Агенты общаются друг с другом по **имени**, а не по id. Сам Claude Code ничего не знает о реестре guildcraft. Всё, что описано ниже, происходит на сервере.

1. У каждого агента есть уникальное имя (сервер отклоняет дубликаты) и внутренний UUID. Сервер хранит реестр, который связывает имя, UUID и PTY, в котором работает `claude` этого агента.
2. Агент вызывает MCP-инструмент `list_villagers`, чтобы увидеть остальных (имя, папка, статус, чем заняты), а затем `send_message` с `to: "<имя>"`.
3. Вспомогательный MCP-скрипт отправляет `POST /api/<id-отправителя>/messages`. Id отправителя берётся из собственного `mcp.json` агента, так сервер понимает, кто говорит.
4. Сервер ищет получателя по имени (без учёта регистра, пробелы по краям игнорируются), находит его PTY по UUID и держит текст в очереди, пока получатель не освободится. Затем вводит его в эту консоль в виде `[Message from <отправитель>]`.
5. Неизвестное имя, получатель не в сети или переполненная очередь возвращаются отправителю как обычное сообщение об ошибке.

Имя не добавляется в промпт модели: агент узнаёт о других через `list_villagers`, а о том, кто ему написал, по префиксу `[Message from ...]`.

## Безопасность

- Сервер слушает только `127.0.0.1`.
- Каждая сессия получает случайный токен, а WebSocket проверяет и токен, и заголовок `Origin`.
- Агенты запускаются с очищенным окружением: переменные `GUILDCRAFT_*` и переменные родительской сессии Claude Code удаляются.

## Требования

- Node.js 20+
- Установленный Claude Code с выполненным входом

## Использование

```sh
npx guildcraft
```

Мастерская откроется в браузере. Порт по умолчанию 7777, его можно изменить через `GUILDCRAFT_PORT`.

Хотите просто осмотреться без сервера и Claude? Откройте веб-приложение с параметром `?demo`, и вы получите симулированных агентов.
